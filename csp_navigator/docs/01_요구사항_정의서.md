# 요구사항 정의서

> 프로젝트: AI 코어 프로젝트 2회차 「RAG 기반 도메인 지식 서비스」
> 서비스명(가칭): **CSP Navigator** — MSP 없이 요구사항에 맞는 저렴한 CSP를 추천하고 인프라를 설계해 주는 RAG
> 문서 버전: **v1.0 (최종)** · 작성일: 2026-10-21 · 최종 수정: 2026-10-23 (실제 구현·검증 결과 반영)
> 표기 규칙: `확인 필요` = 출처로 아직 확인하지 않은 사실, `(더미)` = 예시용 가짜 값, `(기본값)` = 임시로 정한 값

## 2. 도메인 정의

### 2.1 서비스 개요
사용자가 **요구사항**(워크로드 종류, 규모, 월 예산, 보안·규제 조건)과 **부문**을 입력하면, 서비스가 색인된 상품 메타데이터와 외부 문서를 근거로 6개 CSP 중 조건을 만족하면서 비용이 낮은 CSP를 추천하고, 상품 조합으로 된 인프라 설계안을 근거 번호와 함께 제시한다.

- 대상 CSP(6): AWS, GCP, NCP(네이버클라우드), NHN Cloud, KT Cloud, SCP(삼성 클라우드 플랫폼)
- CSP는 사용자가 고르지 않고 **RAG가 추천**한다.

### 2.2 부문 정의

| 부문 | 코드 | 정의 | 추천 시 핵심 판단 기준 |
|---|---|---|---|
| 공공 | `public` | 정부·공공기관·공기업이 따라야 하는 요건(예: 클라우드 보안인증 등)을 만족해야 하는 환경 | 공공 요건 충족 여부(메타 `public_support`)가 1차 필터. 비용은 그다음 |
| private | `private` | 기업용 완전 폐쇄 사설망 환경 | 폐쇄망·전용 회선·사설 연결 지원 여부(메타 `closed_network_support`) |
| 학습용 | `learning` | 개인·교육 목적의 저비용 환경 | 최저 비용, 무료 티어·크레딧(`free_tier`) |

## 3. 도메인 선택 조건 충족 근거 (명세 2.1)

### 3.1 항목 메타데이터 — 출처와 건수

- **항목 단위**: CSP별 상품 1건(예: "NCP Server 표준형 2vCPU" 같은 사양 단위). CSP 6곳만으로는 100건이 되지 않으므로 상품을 항목으로 삼는다.
- **목표 건수**: 108건 이상 (CSP당 18건 × 6)

| 분류 | 코드 | CSP당 목표 | 6곳 합계 |
|---|---|---|---|
| 컴퓨팅 | CMP | 5 | 30 |
| 데이터베이스 | DB | 4 | 24 |
| 스토리지 | STG | 3 | 18 |
| 네트워크 | NET | 4 | 24 |
| 보안 | SEC | 2 | 12 |
| **합계** | | **18** | **108** |

- **출처**: 각 CSP 공식 상품 소개·요금 페이지(직접 확인해 수기 구성). 항목마다 `source_url`과 `checked_at`(확인일)을 기록한다.
- **확보 결과(완료)**: 실제 상품 **108건** 확보(CSP별 18건, 분류별 CMP 30 · DB 24 · STG 18 · NET 24 · SEC 12, 확인일 2026-10-21). 비용 계산용으로 서버 가격표 1,708행과 Block Storage 단가 30종, KISA CSAP 인증 현황 8행을 함께 확보했다. 원본: `data/sources/`, 변환 결과: `csp_navigator/data/processed/products.json`.

### 3.2 외부 문서 출처와 이용 조건

| 출처 종류 | 코드 | 예 | 수집 방식 | 이용 조건 |
|---|---|---|---|---|
| CSP 공식 웹 문서 | `web` | 상품 설명서, 요금 안내, 리전·연결 가이드, 법령·고시 원문 페이지 | Requests로 HTML 수집 → 본문 텍스트 추출 | 수집 전 robots.txt 확인(2026-10-23): AWS·GCP 허용, **NCP 요금 페이지·KT 상품 페이지는 불허 → 수집하지 않음**. 이용약관의 자동 수집 조항은 **확인 필요** |
| PDF 자료 | `pdf` | 「클라우드컴퓨팅서비스 보안인증에 관한 고시」(과기정통부고시 제2023-4호, 10쪽) | 국가법령정보센터 PDF 저장 → 쪽 단위 텍스트 추출 | 저작권법 제7조(고시는 보호받지 못하는 저작물), 출처 표기. KISA 해설서·FAQ는 공공누리 표시 **확인 필요**라 등록하지 않음 |
| 한국어 위키백과 | `wiki` | 클라우드 컴퓨팅, 아마존 EC2 등 개념 문서 | MediaWiki API(연락처 포함 User-Agent) | CC BY-SA 4.0(2023-06 이후 편집분), 이전 편집분 CC BY-SA 3.0 — 2026-10-22 확인 |
| 수집 결과 요약 | `summary` | CSAP 인증 현황, 제도 변경, 계정 단위 무료 혜택, 로그인 필요 정보 | 1일차 수집 결과 md에서 생성 | 각 원출처 조건을 따름(사실만 요약) |
| 공공데이터(선택) | `public_data` | — | — | 이번 구현에서는 사용하지 않음 |

- 출처별 이용 조건은 `csp_navigator/docs/sources.md`에 URL·확인일과 함께 기록했다(NF2007).

### 3.3 근거 없이 답하면 틀리거나 위험해지는 질문

| # | 질문 | 근거 없이 답하면 생기는 문제 |
|---|---|---|
| Q1 | 지방자치단체 민원 시스템을 클라우드로 옮기려 한다. 공공 요건을 충족하는 CSP는 어디인가? | 인증 보유 현황은 시점마다 바뀌므로 기억으로 답하면 규제 위반 위험 |
| Q2 | 인터넷과 완전히 분리된 사내망에서만 접근하는 ERP를 구성하려면 어떤 상품이 필요한가? | 폐쇄망 지원 방식(전용 회선, 사설 연결)이 CSP마다 달라 일반론으로는 잘못된 설계가 나옴 |
| Q3 | 월 예산 5만 원 안에서 학습용 웹 서버 + DB를 띄울 수 있는 가장 저렴한 조합은? | 요금은 수시로 바뀌므로 근거 없이 답하면 금액이 틀림 |
| Q4 | 서울 리전에서 2vCPU·8GB 서버를 월 730시간 쓰면 CSP별 비용 차이는? | 리전·사양별 단가를 모르면 비교 자체가 불가능 |
| Q5 | 공공기관이 외부 SaaS가 아닌 IaaS로 구성할 때 데이터 저장 위치 요건은? | 규제 해석을 추측하면 위험 |

### 3.4 위험 도메인 여부와 면책 문구
- **해당함**: 비용과 규제 준수 판단이 걸리는 도메인이다.
- **면책 문구(화면 상단 고정 + 답변 하단 첨부)**
  > 요금, 인증 보유 현황, 리전 정보는 수시로 바뀔 수 있습니다. 이 답변은 색인된 문서를 근거로 한 참고용이며, CSP의 공식 견적이나 보안·법률 전문가의 검토를 대신하지 않습니다. 각 근거의 확인일을 함께 확인하세요.

## 4. 기능적 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 | 우선순위 |
|---|---|---|---|---|
| F2001 | 데이터 | 상품 메타데이터 적재 | CSP 6곳의 상품 메타데이터(108건 이상)를 로드하고, 상품 1건을 CSP·상품명·분류·사양·요금·리전·부문 지원 여부·설명이 이어진 하나의 색인 텍스트로 구성한다. | 필수 |
| F2002 | 색인 | 메타데이터 색인(RAG 1) | 상품 색인 텍스트를 임베딩하여 `csp_product_meta` 컬렉션에 항목당 1청크로 색인한다. 청크 ID를 항목 ID로 고정해 재실행 시 중복이 생기지 않으며, 색인 건수를 화면에 표시한다. | 필수 |
| F2003 | 프롬프트 | 검색어 추출(프롬프트1) | 클라우드 아키텍트 역할 프롬프트로 선택 상품과 질문에서 외부 문서 검색어를 JSON 배열로 추출한다. 선택 상품의 공식 문서(`source_url`)는 항상 검색 대상에 포함한다. 같은 상품·부문·질문을 다시 물으면 이전 검색어를 그대로 다시 쓴다(NF2002). | 필수 |
| F2004 | 수집 | 외부 문서 수집(프롬프트2) | 출처별로 후보 문서를 모은 뒤, 선별 프롬프트로 제목·요약만 보고 색인할 문서를 고른다. 선택 상품 자체의 공식 문서는 선별·길이 규칙과 관계없이 항상 수집한다. 본문과 원문 출처(URL 또는 파일명·쪽)를 저장하고, 이미 수집한 검색어는 다시 수집하지 않는다. | 필수 |
| F2005 | 색인 | 외부 문서 색인(RAG 2) | 수집 문서를 설정의 청크 크기·중복 길이로 분할해 `csp_external_docs` 컬렉션에 색인한다. 청크 ID는 `항목ID:문서ID:순번`이며 문서 제목·원문 출처·항목 ID·CSP·부문 태그·출처 종류를 함께 저장한다. | 필수 |
| F2006 | 검색 | 근거 검색 및 병합 | 선택 상품의 메타 청크는 검색 없이 항상 포함하고, 외부 문서는 질문과의 의미 유사도로 검색한다. 두 결과를 병합하고 청크 ID 기준으로 중복을 제거한다. Top-k는 설정으로 조정한다. | 필수 |
| F2007 | 생성 | 근거 기반 답변 생성(프롬프트3) | LangGraph `retrieve`/`generate` 두 노드로 구성한다. 답변 생성 프롬프트에 따라 검색된 근거만 사용하고, 근거마다 출처 유형(상품 메타데이터/외부 문서)을 구분하며, 근거가 없으면 "문서에서 확인되지 않음"이라고 답한다. | 필수 |
| F2008 | 생성 | 근거 표시 | 답변 주장마다 `[근거 n]`을 붙이고, 실제 인용된 근거만 제목·원문 출처·확인일과 함께 표시한다. 인용된 근거가 없으면 그 사실을 화면에 안내한다. | 필수 |
| F2009 | UI | 상품 선택 및 질의응답 | 사이드바에서 CSP·분류로 좁혀 상품을 선택하고 채팅으로 질문한다. 대화 기록은 상품별로 따로 유지한다. | 필수 |
| F2010 | 서비스 | CSP 추천·인프라 설계(특화 기능) | 요구사항(워크로드·규모·예산·보안 조건)과 부문을 입력하면 조건을 만족하는 CSP 후보를 비교하고, 가장 적합하고 저렴한 CSP와 상품 조합 설계안을 근거 번호와 함께 제시한다. | 필수 |
| F2011 | 서비스 | 조건 기반 상품 탐색 | "서울 리전, 폐쇄망 지원, 월 3만 원 이하 MySQL"처럼 자연어 조건을 입력하면 메타 색인에서 후보를 찾은 뒤 LLM이 조건에 맞는 상품만 카드로 보여준다. 금액·vCPU·메모리 조건은 LLM이 숫자만 뽑고 비교는 코드가 한다. 카드를 누르면 그 상품의 대화로 이어진다. | 필수 |
| F2012 | UI | 진행 상태 및 안내 | 문서 수집·답변 생성 중 진행 상태를 표시하고, 색인 없음·API 키 누락·검색 결과 없음 안내와 면책 문구(3.4)를 표시한다. | 필수 |
| F2013 | UI | 프론트엔드 직접 구현 | HTML·CSS·JavaScript 화면과 FastAPI 서버를 분리하고 요청·응답 JSON 형식을 정의한다. 질문 입력, 답변, 근거 표시, CSP 추천을 제공한다. | 심화 |
| F2014 | 검색 | MMR 검색 적용 | (선택하지 않음) 설정의 `search_type`만 유지한다. | 심화(미선택) |
| F2015 | 품질 | RAG 전후 품질 비교 | 3.3의 질문을 포함한 대표 질문 5개 이상을 RAG 없이/있이 답하게 하고, 사실 정확성·근거 제시·모름 인정 세 기준으로 비교 문서를 작성한다. | 심화 |
| F2016 | 수집 | 여러 문서 출처 결합 | CSP 공식 웹 문서, PDF, 위키백과를 함께 색인하고 근거에 출처 종류를 구분해 표시한다. 출처별 수집·청킹 방식 차이와 이유를 설계문서에 적는다. | 심화 |
| F2017 | 서비스 | 부문 필터 | 부문 선택에 따라 메타데이터 필터(공공 지원·폐쇄망 지원)를 검색 단계에 적용해, 조건을 만족하지 않는 상품이 추천 근거에 섞이지 않게 한다. 값이 `확인 필요`인 상품은 제외하지 않고 "확인 필요"로 표시한다. | 추가 |
| F2018 | 서비스 | 예상 월 비용 산출 | 추천 설계안의 상품별 단가 × 수량 × 사용 시간으로 예상 월 비용을 계산하고 계산식을 함께 보여준다. 계산은 LLM이 아닌 코드로 하며, 단가 출처와 확인일을 표시한다. | 추가 |
| F2019 | 데이터 | 데이터 최신성 표시 | 근거와 상품 카드에 확인일을 표시하고, 설정한 기준일(기본값 90일)보다 오래된 데이터는 "재확인 권장"으로 표시한다. | 추가 |

## 5. 비기능적 요구사항
