# RAG 파이프라인 설계문서

> 프로젝트: AI 코어 프로젝트 2회차 「RAG 기반 도메인 지식 서비스」 — CSP Navigator
> 문서 버전: **v1.1 (최종)** · 작성일: 2026-10-22 · 최종 수정: 2026-10-23 (실제 GMS 검증 결과·수정 사항 반영) · 기준: 요구사항 정의서 v1.0
> 표기: `확인 필요` = 출처로 확인하지 않은 사실, `(기본값)` = 임시로 정한 값

## 1. 전체 구조

```
[1일차 수집 결과 md·CSV] ──prepare_data──▶ data/processed/*.json ──build_index──▶ Chroma
                                                                         ├─ csp_product_meta   (RAG 1)
                                                                         └─ csp_external_docs  (RAG 2)
질문 ─▶ ① 검색어 추출(프롬프트1)
      ─▶ ② 수집: 공식 문서(항상) + 출처별 후보(web/pdf/wiki) ─▶ 선별(프롬프트2) ─▶ 본문 저장·청킹·색인
      ─▶ ③ LangGraph  retrieve ─▶ generate(프롬프트3) ─▶ 답변 + [근거 n] + 인용 근거 목록
추천 ─▶ 요구사항 → 설계 규칙(코드) → CSP 6곳 비용 계산(코드) → 부문 필터 → 근거 고정 + 부문 문서 검색 → 프롬프트3
탐색 ─▶ 메타 색인 유사도 검색(부문 where 필터) → 조건 해석·선택(LLM) → 금액 조건 비교(코드) → 카드
```

모듈 분리(NF2005): `data_prep`(도메인 코드 전부) → `vectorstore` → `rag` → `services` → `ui`/`api`. 화면은 `services.get_service()`만 부르며, UI 프로토타입의 `NavigatorService` 메서드(get_status · list_products · get_product · ask · recommend · explore)를 그대로 구현했다.

## 2. 컬렉션 구조

| 컬렉션 | 단위 | 청크 ID | 임베딩 본문 |
|---|---|---|---|
| `csp_product_meta` | 상품 1건 = 1청크 (108건) | 항목ID (`NCP-CMP-01`) | CSP·상품명·분류·사양·요금 원문·원화 환산·리전·공공·폐쇄망·무료 티어·설명·출처·확인일을 줄로 이은 텍스트 (`products.index_text`) |
| `csp_external_docs` | 문서 청크 | `항목ID:문서ID:순번` (공통 문서는 `COMMON:문서ID:순번`) | `[문서 제목]` + 청크 본문 |

거리 함수는 코사인(`hnsw:space=cosine`). 같은 ID로 다시 넣으면 덮어쓰므로(upsert) 재실행해도 중복이 생기지 않는다(F2002 확인: 두 번 색인해도 건수 동일).

### 2.1 메타 청크 메타데이터

| 키 | 예 | 쓰임 |
|---|---|---|
| item_id, csp, category, role, name, region | `NCP-CMP-01`, `NCP`, `CMP`, `server` | 표시·필터 |
| billing_unit, unit_price_krw | `hour`, `119.0` | 탐색 카드 |
| public_status / closed_status / free_status | `ok` · `unknown` · `fail` | **부문 필터를 검색 단계에 적용**(F2017). `fail`만 거르고 `unknown`(확인 필요)은 남긴다 |
| source_url, checked_at, source_type=`meta` | | 근거 표시(F2008·F2019) |

### 2.2 외부 문서 청크 메타데이터

| 키 | 설명 |
|---|---|
| title | 문서 제목 |
| source | 원문 출처. URL, PDF는 `파일명 · n쪽` |

| source_type | `web` · `pdf` · `wiki` · `summary` |
| keyword | 이 문서를 고르게 한 검색어 |

## 3. 수집·청킹·색인 흐름

### 3.1 상품 메타 (RAG 1)

1. `prepare_data.py`가 1일차 수집 결과 md의 ① 표 6개(CSP별 18행)를 읽어 `products.json`으로 바꾼다. 원본은 수정하지 않는다.
2. 요금 원문을 구조화한다(`domain.parse_price`): 통화·금액·과금 단위(`시간`, `월`, `일`, `GB-월`, `10GB-시간` 등)·수량 단위(`연결`, `포트`, `Web ACL` …)·추가 과금. 108건 중 107건이 구조화되고, DynamoDB(`쓰기 … 백만 WRU, 읽기 …`) 1건은 복합 요금이라 자동 계산에서 뺀다.
3. 원화 환산은 로드할 때 설정값으로 한다(`products.normalize_price`): USD × 1,334.03원(기본값), GB-시간 × 월 시간(NCP·NHN 720시간, 그 외 730시간), 일 단가 × 30일(기본값). 환율을 바꿔도 변환을 다시 돌리지 않아도 된다.
4. 역할을 붙인다(`classify_role`): server / db_mysql / storage_object / net_vpn / net_dedicated / sec_waf … 설계안 조합에 쓴다. 폐쇄망 열의 확인값(`지원(전용회선)`, `지원(IPsec VPN)`)을 상품명보다 먼저 본다(9장 문제 1).
5. `build_index.py`가 상품마다 색인 텍스트 1개를 만들어 `csp_product_meta`에 넣는다.

### 3.2 외부 문서 (RAG 2)

| 단계 | 처리 | 근거 요구사항 |
|---|---|---|
| ① 검색어 | 프롬프트1이 선택 상품 텍스트 + 부문 + 질문으로 JSON 배열(최대 4개) 생성. **같은 상품·부문·질문이면 이전 검색어를 캐시에서 다시 쓴다**(9장 #14) | F2003·NF2002 |
| ② 공식 문서 | 선택 상품의 `source_url`은 선별·길이 규칙 없이 항상 수집 시도(이미 색인돼 있으면 생략) | F2003·F2004 |
| ③ 후보 | 아직 수집하지 않은 검색어마다 출처별 최대 4건(아래 표) | F2004·NF2002 |
| ④ 선별 | 프롬프트2가 후보의 **제목·요약만** 보고 최대 3건 선택 | F2004 |
| ⑤ 본문 | 문서 캐시 → 없으면 수집. 본문 300자 미만은 버림(기본값), 30,000자에서 자름(기본값) | F2004 |
| ⑥ 색인 | 출처별 청킹 → `csp_external_docs` upsert. 검색어 → 문서ID를 캐시에 기록 | F2005·NF2002 |

**출처별 수집·청킹 차이 (F2016)**

| 출처 | 후보 찾기 | 본문 가져오기 | 청킹 | 이유 |
|---|---|---|---|---|
| CSP 공식 웹 문서 (`web`) | `web_catalog.json`(상품 출처 URL 44개 + 공공 요건 원문 페이지)과 검색어 토큰 겹침 | robots.txt 확인 → HTML → script·nav·footer 제거 후 본문 텍스트 | 빈 줄 → 줄 → 문장 끝 순 | 범용 검색 API가 없어, 1일차에 확인한 공식 URL 목록 안에서만 고른다. 표는 셀을 ` | `로 이어 행 단위가 남게 했다 |
| PDF (`pdf`) | `data/pdf/catalog.json`에 **사람이 이용 조건을 확인하고 등록한 파일만** | `pypdf`로 쪽별 텍스트, 쪽 텍스트는 캐시 | **쪽 단위로 먼저 나눈 뒤** 쪽 안에서 자름 | 청크가 두 쪽에 걸치지 않아 출처를 `파일명 · n쪽`으로 정확히 표시할 수 있다. 현재 등록: 「클라우드컴퓨팅서비스 보안인증에 관한 고시」(10쪽, 저작권법 제7조). KISA 자료는 공공누리 표시가 확인되지 않아 등록하지 않았다 |
| 한국어 위키백과 (`wiki`) | MediaWiki `list=search`로 3배수를 받아 검색어와 제목·스니펫의 단어 겹침으로 다시 순위를 매기고 무관한 문서는 버림(9장 #12) | `prop=extracts&explaintext=1` 평문 | `== 절 ==` 경계를 먼저 존중 | 개념 문서는 절 단위가 의미 단위라 절을 넘는 청크를 줄인다 |
| 수집 결과 요약 (`summary`) | 색인 시 한 번(공통 문서 4개: CSAP 현황·제도 변경·계정 단위 무료 혜택·로그인 필요 정보) | 1일차 md에서 생성 | 줄 단위 | 한 줄이 한 사실(예: CSP 1곳의 인증 1건)이라 줄 경계가 가장 자연스럽다 |

**출처 예절 (NF2006)**: 연락처가 들어간 User-Agent(`CSPNavigator/0.1 (연락처) python-requests/2.34.2`), 같은 호스트 1초 간격(기본값), 429·5xx·연결 오류는 1.5초 × 2ⁿ 지수 백오프 최대 4회, `Retry-After` 준수. robots.txt가 없으면(4xx) 허용, 읽지 못하면(5xx·네트워크) 수집하지 않는다.

## 4. 병합·중복 제거 (F2006)

`rag/graph.py`의 `retrieve_evidences`:

1. **선택 상품 메타 청크** — 검색 없이 ID로 가져와 1번 근거로 고정.
2. **선택 상품을 다룬 문서** — `item_id = 선택 상품` 조건으로 질문 유사도 상위 `own_doc_k`(2, 기본값)개. 공식 문서가 여기 들어온다.
3. **전체 외부 문서** — 부문 태그(`sector_<부문> = true`) 필터를 건 유사도 검색 `top_k`(5)개.
4. 1 → 2 → 3 순서로 합치고 **청크 ID로 중복 제거**. 최대 `max_evidences`(8)개로 자르되, 1·2(와 추천 화면의 고정 근거)는 개수 제한보다 우선한다.

추천 화면은 1·2 대신 **설계안 각 줄의 단가 출처**(상품 메타 청크 또는 가격표 행)를 고정 근거로 앞에 두고, 3을 부문·워크로드 질의로 검색한다.

## 5. 프롬프트

전문은 `cspnav/rag/prompts.py`. 화면에는 노출하지 않는다(NF2004).

| | ① 검색어 추출 | ② 후보 문서 선별 | ③ 답변 생성 |
|---|---|---|---|
| 역할 | 6개 CSP·국내 공공 요건에 정통한 클라우드 아키텍트 | 클라우드 기술 문서 선별 담당자 | MSP 없이 CSP를 고르려는 사용자를 돕는 비용·인프라 설계 상담가 |
| 입력 | 선택 상품 색인 텍스트, 부문 설명, 질문 | 질문, 선택 상품, 후보의 id·출처 종류·제목·요약(200자) | 부문, 질문, [계산 결과](추천 화면), 번호 붙은 근거(출처 유형·제목·출처·확인일·본문) |
| 출력 | JSON 문자열 배열만 | 후보 id의 JSON 배열만(없으면 `[]`) | 마크다운 목록 위주 한국어 700자 안팎 |
| 핵심 규칙 | 최대 4개, 상품명 포함 1개 + 일반 개념어 1개 이상 | 최대 3개, 본문을 보지 않음, 중복 내용은 하나 | 근거에 있는 사실만, 문장마다 `[근거 n]`, 없는 번호 금지, 금액은 근거·계산 결과 값만, '확인 필요'는 단정 금지, 근거가 없으면 "문서에서 확인되지 않음." |
| 형식 오류 대응 | 파싱 실패 시 "JSON 배열만 다시" 1회 재요청, 그래도 실패하면 `CSP 상품명` 1개로 진행 | 재요청 1회, 실패 시 선택 없음 | 없는 근거 번호는 `strip_invalid`로 지우고, 실제 인용 번호만 `cited`로 |

(+) 조건 탐색 해석 프롬프트(F2011): 후보 상품 목록 안에서만 고르고, 금액·vCPU·메모리 비교는 하지 말고 `max_monthly_krw`·`min_vcpu`·`min_memory_gb` 숫자만 내게 한다. **비교는 코드가 한다** — 실제 검증에서 LLM이 "1vCPU라 제외"라고 적고도 그 상품을 결과에 넣은 사례가 있었다(9장 #13).

2026-10-23 실제 검증 후 바꾼 점
- 프롬프트3 규칙 2: 범위 표기(`[근거 1~3]`)·괄호 안 설명을 쓰지 말 것, '문서에서 확인되지 않음' 문장에는 근거 번호를 붙이지 말 것. 코드도 이를 보강한다(`citations.py`가 `[근거 1~3]`·`(근거 1, …)`을 읽어 `[근거 1, 2, 3]`로 통일하고, '확인되지 않' 줄의 번호는 지움).
- 프롬프트3 규칙 6: 근거가 없으면 질문과 상관없는 정보를 덧붙이지 말 것.
- 상품 질의응답도 추천 화면처럼 **선택 상품의 예상 월 비용을 코드로 계산해 [계산 결과]로 넘긴다**(LLM이 USD→원 환산을 틀린 사례, 9장 #17).

모델 호출: `ChatOpenAI(model, api_key, base_url)` — GMS는 OpenAI 호환 주소라 langchain-openai를 그대로 쓴다. `temperature`는 설정값이 있을 때만 넘긴다(기본 `null`). 일부 추론형 모델이 temperature를 받지 않을 수 있어서다(모델별 지원 여부 확인 필요).

## 6. 설정값과 근거, 바꾸면 달라지는 점

모든 값은 `settings.json`에 있고 코드 수정 없이 바꾼다.

| 설정 | 초기값 | 정한 이유 | 키우면 | 줄이면 |
|---|---|---|---|---|
| `chunking.*.chunk_size` | 1,000자 | 명세 시작값. 요금표 한 블록(상품 몇 줄+단서 조항)이 한 청크에 들어가는 크기 | 문맥은 넓어지나 질문과 무관한 내용이 섞여 유사도가 흐려짐, 프롬프트 길이 증가 | 단가와 단서("회선 비용 별도")가 다른 청크로 갈라질 위험 |
| `chunking.*.chunk_overlap` | 200자 | 명세 시작값. 경계에 걸린 문장·표 행을 양쪽 청크에 남김 | 중복 청크가 늘어 Top-k 자리를 같은 내용이 차지 | 경계에서 문장이 잘려 근거가 불완전 |
| `retrieval.top_k` | 5 | 메타 1 + 상품 문서 2와 합쳐 최대 8개 근거 — 700자 답변에 인용 가능한 분량 | 재현율↑, 잡음·토큰↑, LLM이 무관한 근거를 인용할 위험 | 공공 요건 문서처럼 질문과 표현이 다른 근거를 놓칠 위험 |
| `retrieval.own_doc_k` | 2 | 선택 상품의 공식 문서를 최소 2청크 보장 | 상품 문서가 근거 대부분을 차지 | 공식 문서가 근거에 안 들어올 수 있음 |
| `retrieval.max_evidences` | 8 | 프롬프트 길이 상한 | — | — |
| `retrieval.search_type` | `similarity` | F2014(MMR) 미선택. 값만 `mmr`로 바꾸면 `fetch_k=20, λ=0.5`로 동작 | `mmr`: 같은 문서의 비슷한 청크가 연달아 뽑히는 것을 줄여 출처가 다양해짐 | — |

**비교 실험 결과** (2026-10-23 실제 GMS, 같은 질문 3개 — 원자료 `03_검증결과.md` 3장)

| 실험 | 결과 | 결정 |
|---|---|---|
| 청크 500/100 · **1,000/200** · 1,500/300 | 공통 문서 8 · 5 · 4청크. 500자에서는 요약 문서 하나가 2청크로 나뉘어 근거 두 자리를 같은 문서가 차지했고, 1,500자는 1,000자와 근거 구성이 같으면서 프롬프트만 길어짐 | 1,000/200 유지 |

| **similarity** · mmr | MMR은 서로 다른 문서 수가 같거나 1개 많았지만(4→5, 6→7) 인용된 근거가 줄었음(6→3) | similarity 유지(F2014 미선택) |

## 7. 근거 표시 방식 (F2007, F2008, F2016, F2019)

- 근거마다 번호·**출처 유형 배지**(상품 메타데이터 / 요금표 / CSP 공식 웹 문서 / PDF 자료 / 한국어 위키백과 / 수집 결과 요약)·제목·원문 출처(URL 링크 또는 `파일명 · n쪽`)·**확인일**·본문 앞 280자를 보여 준다.
- 답변 본문의 `[근거 n]`을 파싱해 **실제로 인용된 근거만** 목록에 남긴다. 검색됐지만 인용되지 않은 근거는 보이지 않는다. 인용이 하나도 없으면 "인용된 근거가 없습니다" 안내를 띄운다.
- 확인일이 90일(기본값)보다 오래된 근거·상품·비용 줄에는 "재확인 권장" 배지를 붙인다.
- 화면 상단 고정 면책 문구 + 모든 답변 하단 면책 문구(요구사항 정의서 3.4 원문).
- FastAPI 응답도 같다: `evidences`에는 인용된 근거만, LLM에 넘긴 본문(`content`)·청크 ID는 빼고 `snippet`만 보낸다.

## 8. 특화 기능 설계 이유

### 8.1 CSP 추천·설계 (F2010) — "계산은 코드, 설명은 LLM"

- 요구사항을 구성 요소로 바꾼다: 서버(가격표 1,708행에서 vCPU·메모리 이상 최저가) · 서버 디스크(단가에 OS 디스크가 없으면 SSD 50GB, 기본값) · DB(MySQL, 2vCPU/4GB 이상 최저가, 학습용은 1/1) · 오브젝트 스토리지 · 사설 연결(폐쇄망 조건 시, 전용회선 → VPN 순, 학습용은 VPN 먼저) · WAF(조건 시) · 로드밸런서(서버 2대 이상).
- 서버는 108건 메타가 아니라 **가격표**에서 고른다. 메타의 컴퓨팅 상품은 CSP당 5개뿐이라 "2vCPU/8GB"처럼 사양을 맞추기 어렵기 때문이다. 가격표 행은 근거 유형 `요금표`로 표시한다.
- 제외 규칙(기본값): 계정 기본료가 따로 붙는 플랫폼(KT D1, 비고에 '기본료'), 이전 세대 플랫폼(NCP Classic). 이유는 설계안 월 비용에 그 기본료가 빠져 실제보다 싸 보이는 것을 막기 위해서다.
- 비용·후보 비교·부문 판단은 모두 코드가 하고, LLM(프롬프트3)은 [계산 결과]와 고정 근거를 받아 이유만 쓴다. LLM이 실패하면 코드가 만든 요약(근거 번호 포함)으로 대신하고 안내한다.
- 선택 규칙: 조건 충족 후보 중 예산 안에서 최저가 → 없으면 최저가(예산 초과 경고) → 동률이면 '확인 필요' 항목이 적은 쪽.

### 8.2 부문 필터 (F2017)

| 부문 | 검색 단계 | 설계 단계 |
|---|---|---|
| 공공 | 메타 검색 `public_status != fail`, 문서 검색 `sector_public = true` | CSP 단위 CSAP 판단: 유효기간 안의 인증이 없으면 제외 · **상·중등급 시스템인데 하등급 인증만 있으면 제외**(AWS·GCP) · 나머지는 '확인 필요'(국내 4사는 공공기관용 별도 플랫폼이 인증 범위) |
| private | 메타 검색 `closed_status != fail`, 문서 검색 `sector_private = true` | 사설 연결 상품(폐쇄망 '지원' 확인된 것만) 필수. 없으면 제외 |
| 학습용 | 문서 검색 `sector_learning = true` | 최저 비용 우선, DB 최소 사양 완화 |

'확인 필요' 값은 **제외하지 않고** 표시한다. 수집 자료의 공공 열이 108건 모두 '확인 필요'이고 폐쇄망은 14건만 확인돼, 확인 필요를 빼면 후보가 거의 남지 않는다. 대신 화면 '확인 필요 항목'에 모두 드러낸다. KT G-Cloud 인증(CSAP-2016-001호)은 유효기간 종료일(2026-10-19)이 지나 유효 인증에서 빠지고, kt cloud PLATFORM 공공기관용(CSAP-2026-010호)으로 판단된다.

### 8.3 예상 월 비용 (F2018)

`services/cost.py`가 줄마다 `단가 × 수량 × 시간 = 소계` 문자열을 만든다. USD는 `(0.104 USD × 1,334.03원/USD) 138.74원/시간 × …`처럼 환산 과정을 남긴다. 공식 월 요금이 있는 상품(NCP·KT 서버)은 월 사용 시간이 730시간 이상이면 공식 월 요금을 쓴다(1일차 메모의 기준). 계산 결과는 VAT 별도, 트래픽·약정 할인 제외.

### 8.4 조건 탐색 (F2011)

메타 색인 유사도 검색(30건, 부문 필터) → LLM이 조건 해석과 후보 선택 → 금액·vCPU·메모리 조건은 코드가 비교 → 낮은 가격 순 카드. 카드의 "이 상품으로 질문하기"는 그 상품의 대화로 이동한다.

### 8.5 데이터 최신성 (F2019)

상품·근거·비용 줄에 확인일을 붙이고 `freshness_days`(90일, 기본값)를 넘으면 "재확인 권장". 1일차 수집 결과는 모두 2026-10-21이라 현재는 표시되지 않으며, 2027-01-20부터 표시된다.
