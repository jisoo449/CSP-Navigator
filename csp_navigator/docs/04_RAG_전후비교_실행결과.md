## Q1. 지방자치단체 민원 시스템을 클라우드로 옮기려 한다. 공공 요건을 충족하는 CSP는 어디인가?

- RAG 쪽 선택 상품: `NHN-CMP-02` Instance m2.c2m4 · 부문 공공

### RAG 없이

지방자치단체 민원 시스템을 클라우드로 전환할 때는 반드시 공공기관 보안 및 행정안전부, 과기정통부의 클라우드 이용 가이드라인을 준수하는 공인된 클라우드 서비스 제공자(CSP)를 선택해야 합니다. 

한국에서 공공기관에 적합한 CSP는 보통 행정안전부 클라우드 보안인증(CSAP)이나 공공기관 클라우드 보안인증을 획득한 사업자를 의미합니다. 대표적인 CSP는 다음과 같습니다.

1. **네이버 클라우드 (NCP)**: CSAP 인증을 받은 공공 전용 클라우드 서비스가 있으며, 공공기관에 특화된 보안 및 관리 기능 제공.

2. **KT 클라우드**: 공공기관용 클라우드 환경, 보안인증 체계 확보, 실시간 모니터링과 보안 대응 체계 운영.

3. **NHN 클라우드**: 공공기관 보안인증 획득, 데이터 분리 및 관리 체계 제공.

4. **AWS, MS Azure, Google Cloud**: 글로벌 CSP들도 국내법과 공공기관 요구사항 맞춤형 공공 클라우드 서비스를 제공 중이며, 일부는 국내 리전을 운영하며 공공기관 특화 보안 인증을 획득.

단, 클라우드 이전 시 민원 데이터의 개인정보 보호법, 국가정보보안기본법, 행정안전부 보안지침 준수를 철저히 검토해야 하며, 민감정보의 암호화, 접근통제, 감사로그 관리, 재해복구 계획 수립 등이 필수 요소입니다. 또한, 공공 클라우드 이용 시 ‘행안부 클라우드 이용 가이드라인’과 ‘클라우드 보안인증제도(CSAP, CCSP)’를 반드시 확인해야 합니다.

결론적으로, 지방자치단체 민원 시스템을 클라우드로 안전하게 이전하고 운영하려면 국내 CSAP 인증을 받은 네이버 클라우드플랫폼, KT 클라우드, NHN 클라우드와 같은 공공 특화 CSP를 우선 검토하며, 글로벌 CSP의 국내 공공 인증 획득 여부와 서비스 조건도 동시에 비교하는 것이 좋습니다. 아울러 보안 및 법적 요구사항 충족을 위한 체계적인 사전 준비와 운영 관리 계획 수립이 필수입니다.

### RAG 사용

지방자치단체 민원 시스템 같은 공공 부문용 클라우드를 선택 시, 공공 요건(클라우드 보안인증, CSAP)을 충족하는 CSP가 1차 조건입니다. 현재 CSAP IaaS 인증 보유 CSP는 다음과 같습니다.

- NHN Cloud(공공기관용) : CSAP 인증서 보유, 유효기간 2022-12-13 ~ 2027-12-12 상태 유지 중[근거 4]
- 네이버클라우드플랫폼(NCP) 공공기관용 : CSAP 인증서 보유, 유효기간 2022-02-24 ~ 2027-02-23 상태 유지 중[근거 4]
- KT Cloud(공공기관용) : CSAP 인증서 보유, 유효기간 2026-03-25 ~ 2031-03-24 상태 유지 중[근거 4, 7]
- 삼성클라우드(SCP) : CSAP 인증서 보유, 유효기간 2024-08-28 ~ 2029-08-27 상태 유지 중[근거 7]

AWS 및 GCP는 현재 하등급 IaaS만 CSAP 인증 범위이며, 상·중등급 공공 시스템에 바로 사용할 수 없습니다[근거 4, 7].

2027년 하반기부터는 국정원 단일 검증 체계가 본격 시행되어 CSAP 제도가 정리될 예정입니다[근거 3], 이에 따라 최신 인증 현황과 인증 체계 변경 사항을 반드시 확인해야 합니다.

요약하면,

- 지방자치단체 민원 시스템 같은 공공 요건을 충족하려면 NHN Cloud 공공기관용, NCP 공공기관용, KT Cloud 공공기관용, SCP 플랫폼 중에서 선택해야 합니다.
- AWS, GCP는 하등급 인증만 보유해 상·중등급 공공 시스템 적용은 부적합합니다.
- 2027년 이후 인증 체계 변경에 따른 추가 검증 및 확인이 필요합니다.

각 CSP별 공공용 인증 여부와 유효기간, CFAP 인증서를 기반으로 공공 요건 충족 CSP를 선정하시기 바랍니다[근거 4, 7]. 무료 티어나 전용 회선 지원 등 상세 제원은 문서 내에서 확인 필요합니다[근거 1, 5].

## Q2. 인터넷과 완전히 분리된 사내망에서만 접근하는 ERP를 구성하려면 어떤 상품이 필요한가?

- RAG 쪽 선택 상품: `KT-NET-02` Connect Hub 1Gbps (Shared) · 부문 private

### RAG 없이

인터넷과 완전히 분리된, 즉 완전 폐쇄망 환경에서만 접근 가능한 ERP 시스템을 구축하려면 다음과 같은 요소와 상품들이 필요합니다.

1. **온프레미스 서버 또는 프라이빗 클라우드**  
ERP 시스템 자체를 인터넷과 단절된 내부 네트워크에 설치해야 합니다. 이를 위해 고객사 내부 데이터센터에 온프레미스 서버를 구축하거나, 퍼블릭 클라우드가 아닌 완전 독립된 프라이빗 클라우드(예: VMware 기반 프라이빗 클라우드)를 도입합니다.

2. **네트워크 격리 솔루션**  
사내망은 인터넷과 물리적으로 분리되어야 하므로 방화벽, 네트워크 세그멘테이션, 내부망 스위치 및 라우터 구성이 필수입니다. 인터넷 접속이 불가능하도록 인터넷 게이트웨이를 차단하고 내부망 장비만으로 네트워크를 구성해야 합니다.

3. **방화벽 및 접근 제어**  
내부 사용자만 해당 ERP에 접근 가능하도록 내부 방화벽 룰 설정과 사용자 권한 관리가 필요합니다. NAC(Network Access Control) 솔루션을 도입해 허가된 디바이스만 접속하게 할 수도 있습니다.

4. **ERP 소프트웨어**  
SAP, Oracle ERP, 더존 ERP 등 인터넷 접속 없이 설치 및 운영 가능한 ERP 패키지를 선택합니다. 클라우드 전용 ERP는 폐쇄망에서 불가능하므로 반드시 온프레미스 설치 버전이어야 합니다.

5. **보안 모니터링 및 백업**  
내부망 침해 탐지 시스템(IDS/IPS), 로그 수집 및 모니터링 도구, 정기적인 백업 솔루션도 구축해야 합니다. 데이터 유출 방지를 위한 USB 제어 솔루션도 고려해야 합니다.

6. **내부 사용자 접근 수단**  
내부 PC 또는 단말기에서 ERP 접속을 위한 워크스테이션, ThinClient, 가상 데스크톱(VDI) 환경을 구성할 수 있습니다.

정리하면, **완전 폐쇄망에서 ERP 운영을 위해 반드시 온프레미스 ERP 설치 + 물리적, 논리적 네트워크 분리(방화벽, 스위치), 접근 제어 솔루션, 내부 보안 및 백업 체계를 갖춘 인프라**가 필요합니다. 퍼블릭 클라우드 기반 서비스는 인터넷 연결 필수이므로 적합하지 않고, 내부 전용 프라이빗 클라우드도 인터넷 분리 정책 하에서는 자체 인프라로 운영해야 합니다.

### RAG 사용

인터넷과 완전히 분리된 사내망에서만 접근하는 ERP 구성 조건에 맞는 상품은 다음과 같습니다.

- KT Cloud의 Connect Hub 1Gbps (Shared) 상품은 폐쇄망·전용 회선·사설 연결을 지원하는 네트워크 상품입니다. 전용 회선과 VPN 연동 허브 기능을 제공하므로, 외부 인터넷과 분리된 사내망 연결에 적합합니다. 월 요금은 140,000원(부가세 별도)이며 Seoul M1 존에서 제공됩니다[근거 1].
- AWS EC2 등 일반 퍼블릭 클라우드는 공개된 정보상 인터넷 연결을 전제로 하며, 사내망 완전 분리 여부 및 전용 회선 제공 여부는 문서에서 확인되지 않습니다. AWS EC2는 가상 서버 인스턴스 제공에 집중하며 네트워크 연결 방식에 대한 폐쇄망 보장 정보는 없습니다[근거 3, 4, 5, 6].

따라서, 인터넷과 완전히 분리된 사내망에서의 ERP 운영을 위해서는 KT Cloud의 Connect Hub 1Gbps (Shared)처럼 전용 회선 기반 폐쇄망·사설 연결을 지원하는 네트워크 상품 이용을 권장합니다. AWS 등 대형 CSP는 해당 조건 충족 여부가 문서에 확인되지 않습니다.

## Q3. 월 예산 5만 원 안에서 학습용 웹 서버 + DB를 띄울 수 있는 가장 저렴한 조합은?

- RAG 쪽 선택 상품: `NCP-CMP-05` Server Micro-g1 (Classic) · 부문 학습용

### RAG 없이

월 5만 원 예산 내에서 학습용 웹 서버와 데이터베이스(DB)를 운영하려면 클라우드 비용 효율성과 관리 편의성을 모두 고려해야 합니다. 핵심은 **저렴한 가상서버(또는 컨테이너) + 무료 또는 저비용 DB 서비스 조합**을 선택하는 것입니다.

1. **클라우드 플랫폼 선택**  
- **네이버 클라우드 플랫폼(NCP), 카카오 클라우드, AWS, GCP, Azure** 중 고려할 수 있으나, 한국 리전과 가격을 감안하면 NCP가 비용 경쟁력이 좋고 한글 지원도 원활합니다.  
- AWS/GCP도 무료 티어 범위 내에서는 충분하지만, 월 5만 원 예산으로 안정 운영 시 유료 리전 요금 발생 가능.

2. **서버(웹서버) 선택**  
- NCP의 경우 ‘스몰 인스턴스’ 혹은 ‘퍼블릭 서버’에서 가상머신을 월 1만~2만 원 초반에 구동 가능.  
- AWS Lightsail, GCP Compute Engine에서 가장 저렴한 인스턴스도 월 1~2만 원대 수준.  
- 또는 컨테이너 오케스트레이션보다 단독 가상머신이 관리 편의 측면에서 유리.

3. **DB 선택**  
- **무료 또는 저렴한 관리형 DB 서비스 추천**  
  - NCP MySQL 기본형(소규모 인스턴스) : 월 1만 원 내외  
  - AWS RDS 프리티어(e.g. db.t2.micro) : 처음 12개월 무료, 이후 소규모 인스턴스 비용 발생  
  - 또는 EC2 내에 MySQL/PostgreSQL 직접 설치하면 DB 추가 비용 없이 서버 비용만 발생.

4. **구성 예시**  
- NCP 스몰 VM (2 vCPU, 2GB RAM) : 약 15,000~20,000원  
- NCP MySQL Basic 인스턴스 : 약 10,000원  
- 총 월 3만 원 내외로 가능, 나머지 금액은 트래픽 등 기타 비용으로 활용.

5. **추가 팁**  
- 데이터 백업 및 모니터링 자동화 권장  
- 테스트 목적이면 서버와 DB를 한 머신에 같이 넣어 비용 절감 가능 (단, 성능 저하 고려).  
- 웹 서버는 nginx 또는 Apache, DB는 MySQL/MariaDB 추천

요약하면 **NCP 저사양 가상서버 + 관리형 MySQL DB 조합이 월 5만 원 이하에서 가장 안정적이고 효율적인 방법**입니다. 직접 설치하는 DB로 구성하면 비용은 더 절감되나 운영 부담이 증가하니 학습 목적이라면 관리형 DB를 활용하는 게 좋습니다.

### RAG 사용

- 학습용 웹 서버 + DB를 월 5만 원 이내로 운영하려면, 먼저 가장 저렴한 웹 서버 인스턴스를 선택해야 합니다.
- 네이버 클라우드 플랫폼(NCP)의 Server Micro-g1 (Classic)은 1vCPU/1GB, 월 13,000원(부가세 별도)으로, 신규 가입자에게는 1년간 무료 티어 제공되어 매우 경제적입니다. 1년 무료 티어를 활용할 경우 서버 비용은 사실상 0원으로 볼 수 있습니다[근거 1].
- AWS EC2 t3.micro 인스턴스 요금은 공식 문서에 시간이 조금 명확하지 않으나, 기본적으로 온디맨드 요금 체계이며, CPU 과부하 시 추가 크레딧 비용이 존재하지만 구체 월 단가는 문서에 나타나지 않습니다[근거 2, 3].
- DB로 AWS DynamoDB를 고려할 때 최소 월 사용 비용은 상당히 높습니다. 예를 들어, Standard 테이블 클래스에서 데이터 스토리지 및 읽기/쓰기 요청이 포함되면 월 325.62 USD(약 40만 원 초과)이며, 스탠다드-IA 테이블 클래스로 전환해도 159.74 USD(약 20만 원 이상)로 예산을 벗어납니다[근거 4, 5].

- 결론:  
  - 서버: NCP Server Micro-g1 (Classic) 신규 가입시 1년간 무료 티어 활용 가능해 가장 저렴함[근거 1].  
  - DB: AWS DynamoDB는 비용 초과, NCP DB 요금과 무료 티어는 문서에서 확인되지 않음.

## Q5. 공공기관이 외부 SaaS가 아닌 IaaS로 구성할 때 데이터 저장 위치 요건은?

- RAG 쪽 선택 상품: `SCP-CMP-04` Virtual Server s2v2m8 (2세대) · 부문 공공

### RAG 없이

공공기관이 외부 SaaS 대신 IaaS(Infra as a Service)를 활용할 경우 데이터 저장 위치에 대한 요건은 매우 엄격합니다. 핵심은 "국내에 데이터 센터가 위치해야 하며, 데이터가 해외로 유출되지 않아야 한다"는 점입니다. 공공기관 정보시스템 운영지침 및 정부 클라우드 가이드라인에 따르면 공공기관의 중요 정보는 반드시 국내에 물리적 서버가 위치한 IaaS 환경에서 저장·관리 해야 하며, 외국 클라우드 제공자의 데이터 센터나 해외로 데이터가 이전되는 것을 제한합니다.

즉, 공공기관이 사용할 IaaS는 다음 조건을 만족해야 합니다.

1. **데이터 센터 위치**: 국내에 위치해야 하며, 클라우드 서비스 제공 기업도 국내 법령 준수 및 데이터 주권 확보가 가능한 사업자여야 합니다.

2. **데이터 주권 보장**: API, 백업, 로그 등 모든 운영·관리 데이터도 해외로 전송되면 안 되고, 모든 저장소가 국내 내에서 유지돼야 합니다.

3. **보안 및 컴플라이언스**: 정보보호관리체계(ISMS), 국가보안기술연구소 검증(PIMS, GDPR 대응 등 추가 요건 준수)과 같은 보안인증을 확보한 클라우드 사업자여야 합니다.

4. **계약 및 법률 요건**: 데이터 처리 및 접근권한에 대한 법률적 검토가 이루어져야 하며, 긴급 대응 시에도 데이터 주권을 침해하지 않는 체계여야 합니다.

요약하면, 공공기관이 IaaS를 활용할 때는 “국내 법령 및 공공기관 정보보호지침에 따라 데이터센터는 국내에 위치하고 중요 데이터는 해외 이전을 금지”하는 조건을 충족해야 하며, 이를 위해 국내 소재 클라우드 전문 사업자를 통해 서비스 계약이 이뤄져야 합니다. 공공기관이 외산 클라우드나 해외 데이터센터가 포함된 IaaS를 사용하면 법적으로 문제가 될 수 있으므로 반드시 국내 인프라를 기준으로 서비스 환경을 구성해야 합니다.

### RAG 사용

공공기관이 IaaS로 클라우드를 구성할 때 데이터 저장 위치 요건 관련 사항은 다음과 같습니다.

- 공공 요건(클라우드 보안인증, 예: CSAP IaaS 인증) 충족이 1차 조건입니다. 삼성SDS SCP의 Virtual Server s2v2m8 (2세대)의 경우 공공기관용 별도 플랫폼은 CSAP IaaS 인증 범위에 속하나, 일반 민간용 요금과 플랫폼은 구분되며, 공공 요건 충족 여부는 '확인 필요' 상태입니다[근거 1].
- 데이터 저장 위치에 대해 삼성SDS SCP 문서에서는 구체적인 요건(지역, 리전 제한 등)은 명시되지 않고 다만 한국 리전을 제공하고 있습니다[근거 1].
- AWS 공식 문서에서는 특정 지역(리전) 내 데이터 전송 시 요금과 보안 정책이 명시되어 있으나, 공공기관 데이터 저장 위치 요건과 직접 관련된 정보는 문서에서 확인되지 않습니다[근거 2, 3, 4, 5, 6].
- 전반적으로, 공공기관은 데이터가 국내 리전에 물리적으로 저장되어야 하는 등 공공 요건에 부합하는 인증과 위치 제한 요건을 반드시 확인해야 하며, 해당 사항은 각 CSP 및 서비스별 인증 범위와 정책에 따라 달라집니다.
- 삼성SDS SCP의 경우 공공기관 전용 플랫폼이 별도 인증범위이며, 일반 공개된 상품은 공공 인증 충족 여부가 확인 필요합니다[근거 1].

요약:
- 공공기관 IaaS 데이터 저장 위치는 공공 요건에 따른 국내 리전 이용 및 보안 인증 충족이 1차 조건입니다.
- 삼성SDS SCP는 공공기관 전용 별도 플랫폼이 CSAP IaaS 인증 대상이며, 일반 상품은 공공 요건 확인이 필요합니다.
- AWS 등 타 CSP 공식 문서에서는 공공 데이터 저장 위치 관련 명확한 요건은 문서에서 확인되지 않습니다.

따라서, 공공기관은 CSP가 제공하는 공공용 별도 플랫폼과 인증 범위를 우선 확인하고, 데이터 저장 위치(지역·리전) 요건 충족 여부를 직접 검증하는 것이 필수입니다.
